# Week 35, 2026 (24–30 August)

## Summary

**Shipped: over-the-air updates.** An appliance can now be updated without a
shell. It checks a private release repository on a timer, shows an admin what
is available, and installs a signed bundle on one button - atomically, with
automatic rollback if the new version does not come up and boot-time repair if
the power goes out mid-swap. Cut as v2.1.0, which is also the first version
the product has ever had a number for.

The design that took the most argument was the swap. Copying new files over a
live install is the obvious approach and the wrong one: it is seconds long,
not atomic, and a power cut in the middle leaves a tree that is half each
version with nothing alive to repair it. Releases now live side by side under
`/opt/irivai-releases`, each with its own virtualenv, and going live is a
single rename of a symlink.

**Also this week** (from the sessions before the OTA work): motion trails,
Zone Switch nodes, per-system page-category permissions, and a run of camera
and template fixes - all recorded in `docs/bug-reports.md`.

**Started: the documentation set.** Requirements, architecture, API, test
plan, defect log and this changelog, one file per deliverable, under `docs/`.
The process they belong to is named in `docs/sdlc.md`.

**Open:** a system streaming healthily can still carry a stale
`camera read failed` string in its state, so its card may show a fault that has
already cleared. Not yet investigated.
